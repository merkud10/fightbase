# AI-тексты для прогнозных снапшотов

Дата: 2026-08-14. Статус: дизайн согласован, ждёт имплементации.

## Проблема

Все страницы `/predictions/[eventSlug]/[fightSlug]` (~87 на цикл) собираются из одинаковых
шаблонных фраз в `scripts/generate-prediction-snapshots.js` — меняются только имена и числа.
Для читателя тексты неотличимы между боями, для поисковиков это шаблонные дубли.

## Решение (вариант A, согласован)

Текстовые поля снапшота (`overview`, `keyEdge`, `fightScript`, `pathA`, `pathB`) для русской
локали наполняет DeepSeek (модель из `DEEPSEEK_MODEL`, сейчас V4-Flash) на основе факт-пакета
из базы. Всё остальное не меняется: UI, проценты, таблица статов, английские шаблоны,
структура страницы. При любом сбое генерации поле остаётся шаблонным.

### Не в объёме (явно)

- Никаких изменений UI/вёрстки и английского контента (EN остаётся шаблонным).
- Никакой собственной вероятностной модели — проценты как сейчас (коэффициенты/эвристика).
- Никаких букмекерских рекомендаций в текстах.

## Архитектура

Новый модуль `scripts/prediction-ai-copy.js` (CommonJS, как соседние скрипты):

- `buildFightFactPack(fight, percents)` — собирает факт-пакет (только данные из базы).
- `buildPrompt(factPack)` — системный+пользовательский промпт, требует строгий JSON.
- `validateAiCopy(parsed, factPack)` — четыре проверки (ниже), возвращает
  `{ ok: true, copy } | { ok: false, reason }`.
- `generateAiPredictionCopy(fight, percents)` — вызов DeepSeek (таймаут 30с, 2 ретрая,
  экспоненциальная пауза), парсинг, валидация. Ошибка → `null` (вызывающий код оставляет шаблон).

`generate-prediction-snapshots.js` вызывает модуль для RU-контента каждого боя и подменяет
пять текстовых полей при успехе. Английский контент и все остальные поля — без изменений.

## Факт-пакет

Только из базы: имена RU (fallback EN), рекорды, весовая, статус в карде (главный/со-главный/
прелимы), дата и название турнира, статистика каждого бойца (SLpM, точность ударов, защита,
TD avg, TD defense, sub avg — только заполненные), последние ≤3 боя (соперник, результат,
метод), вероятности percentA/percentB и их источник (котировки/эвристика). Отсутствующие
блоки не попадают в промпт.

## Контракт промпта

- Ответ — строго JSON: `{overview, keyEdge, fightScript, pathA, pathB}`, все поля строки.
- Русский язык; имена бойцов только в именительном падеже.
- Запрещено: факты и числа вне факт-пакета; беттинг-лексика («ставьте», «зайдёт», «экспресс»);
  выдуманные травмы/цитаты/история встреч.
- Длина: главный/со-главный бой ~120–160 слов на поле, прелимы ~60–90.

## Валидация (последовательно, любой провал → шаблон + причина в лог)

1. Валидный JSON, все пять полей — непустые строки.
2. Красные флаги: доля латиницы >10% в любом поле; паттерны из `RED_FLAG_RULES`
   (переиспользуются из `generate-ai-predictions.js`, выносятся в общий модуль).
3. Числовой контроль: каждое число в тексте (кроме номеров раундов 1–5) должно встречаться
   в факт-пакете (рекорды сравниваются как строки «28-1-0», проценты — как целые).
4. Длина каждого поля в словах в пределах 0.5×–2× от середины целевого диапазона
   (главные бои: середина 140, прелимы: 75).

## Схема БД

Миграция: в `FightPredictionSnapshot` добавляются `aiContentHash TEXT NULL` и
`aiGeneratedAt TIMESTAMP NULL`. Обе nullable — существующие строки не трогаются.

## Когда генерировать и перегенерировать

`aiContentHash = sha256(fighterA.id + fighterB.id + eventId + roundedPercentA)`, где
`roundedPercentA` — percentA, округлённый к ближайшим 10 п.п.

- Хэша нет (новый бой или старый снапшот) → генерируем.
- Хэш совпал → тексты не трогаем (ежедневный прогон ничего не перезаписывает — страницы
  стабильны для SEO).
- Хэш изменился (замена соперника, перенос боя, сдвиг вероятности через границу 10 п.п.)
  → перегенерируем.
- Фоллбэк на шаблон хэш НЕ записывает — следующий прогон попробует снова.

## Запуск и операционка

- Внутри существующей ежедневной джобы (там же, где сейчас снапшоты), последовательно по боям.
- Полный кард ~87 вызовов ≈ 5–10 минут, стоимость — центы (V4-Flash, кэш системного промпта).
- Если фоллбэков за прогон >20% — `recordSystemEvent` уровня warn (видно в /admin/health).
- Флаг `--dry-run --limit N`: печатает тексты в stdout, ничего не пишет — для глазной
  проверки перед первым включением.
- Выключатель: env `PREDICTION_AI_COPY=0` полностью отключает генерацию (остаются шаблоны).

## Тесты

- `tests/prediction-ai-copy.test.ts`: валидатор — кривой JSON, пустые поля, латиница,
  красные флаги имён, числа вне факт-пакета, длины; хэш — стабильность и смена при замене
  соперника/сдвиге процентов через границу.
- Генерация с замоканным fetch: успешный путь и фоллбэк при HTTP 500/таймауте.
- Существующие тесты и смоук не трогаются.

## Риски

- Качество русского у V4-Flash на бедных данных → короткая целевая длина для прелимов,
  валидация, dry-run перед включением.
- DeepSeek недоступен в момент прогона → фоллбэк на шаблоны, попытка в следующий прогон.
- «Дышащие» страницы → хэш-гейт: без значимых изменений текст не перегенерируется.

# Сопоставление рейтинга UFC с профилями бойцов

Дата: 2026-09-01

## Проблема

На `/ru/rankings` 124 из 256 ячеек показывают серый кружок с буквой и надпись
«Ожидается» вместо ссылки на профиль. Среди них топовые бойцы: Гейджи, Аспинэлл,
Стрикленд, Пантожа, Морено, Фигередо, Стерлинг, Пимблетт, Блэйдс.

Это не пробел в данных. Все перечисленные бойцы есть в базе и заполнены: фото,
возраст, рост, размах, официальная статистика UFC, биография. Ломается
сопоставление строки рейтинга с записью `Fighter`.

### Причина

1. `lib/ufc-rankings.ts` запрашивает `https://www.ufc.com/rankings`. UFC.com
   определяет российский IP сервера и редиректит на `https://ufc.ru/rankings` —
   русскую версию. Английская версия с этого IP недоступна: `/en/rankings`
   уводит на страницу поиска, прокси нет.
2. С русской версии парсятся русские имена («Джастин Гейджи») и русские слаги
   (`dzhastin-getzhi`). Часть слагов — переиспользованные внутренние
   идентификаторы UFC, не имеющие отношения к бойцу: Тацуро Таира →
   `dzheremaya-uells-0`, Бенуа Сэн-Дени → `mariya-agapova-0`, Джо Пайфер →
   `kanako-murata-1`.
3. `getUfcOfficialRankingLinks` (`lib/db/fighters.ts:337`) матчит по английскому
   слагу и по точному совпадению имени с `name` либо `nameRu`. `dzhastin-getzhi`
   не равно `justin-gaethje`, а «Джастин Гейджи» не равно `nameRu` в базе
   («Джастин Гаетдже»). Промах по обоим ключам даёт «Ожидается».

Из 218 уникальных записей снимка не резолвятся 70 (32%). На странице их 124 из
256, потому что бойцы из pound-for-pound повторяются в своих дивизионах.

### Найденное решение

Страница атлета на ufc.ru отдаёт точный английский слаг в `hreflang`:

```
ufc.ru/athlete/dzheremaya-uells-0
  → <link rel="alternate" hreflang="en" href="https://ufc.ru/athlete/tatsuro-taira">
```

Проверено на пяти худших случаях — `justin-gaethje`, `tatsuro-taira`,
`benoit-saint-denis`, `tom-aspinall`, `joe-pyfer`. Все совпадают со слагами в
нашей базе один в один.

### Отклонённые варианты

**Нечёткое сопоставление по русским именам** (нормализация плюс расстояние
Левенштейна к `nameRu`). Не требует сети, но «Гейджи» против «Гаетдже» такой
матчинг не вытягивает, а подменённые слаги не чинит вовсе. Закрыл бы примерно
половину промахов ценой риска подставить чужой профиль. Честное «Ожидается»
лучше неверной ссылки.

**Ручная таблица соответствий.** Точно, но каждое обновление рейтинга приносит
новые имена, и таблицу пришлось бы дополнять вручную бессрочно.

## Архитектура

Вводится одна новая ответственность: по русскому слагу UFC узнать английский.
Она оформлена отдельно от парсера рейтингов и от страницы.

```
refreshUfcRankingSnapshot()
  ├─ fetchUfcOfficialRankings()      без изменений, отдаёт ru-слаги
  ├─ resolveEnglishAthleteSlugs()    новое: ru-слаг → en-слаг
  └─ planUfcRankingSnapshotRefresh() без изменений
```

Резолвер подменяет `officialSlug` на английский до записи снимка. Благодаря
этому `getUfcOfficialRankingLinks` и `app/rankings/page.tsx` не меняются:
они уже умеют матчить по английскому слагу, им просто перестают приходить
русские. Рендер не затрагивается.

## Компоненты

### `lib/ufc-athlete-slug.ts`

`extractEnglishAthleteSlug(html: string): string | null`.

Достаёт из разметки `<link rel="alternate" hreflang="en" href="…/athlete/SLUG">`
и возвращает `SLUG`. Возвращает `null`, если ссылки нет или href не содержит
`/athlete/`. Сети не касается, поэтому тестируется на фикстуре реальной
разметки.

### Модель `UfcAthleteSlugAlias`

Добавляется в `prisma/schema.prisma` и `prisma/schema.postgres.prisma`, плюс
миграция.

| Поле | Тип | Описание |
| --- | --- | --- |
| `officialSlug` | String `@id` | Русский слаг из ufc.ru |
| `englishSlug` | String | Разрешённый английский слаг |
| `resolvedAt` | DateTime | Когда соответствие установлено |

Соответствие «ru-слаг → en-слаг» неизменно, поэтому TTL не предусмотрен: в сеть
резолвер ходит только за слагами, которых нет в таблице. После первого
заполнения обновление рейтинга почти не делает внешних запросов.

### `lib/db/ufc-athlete-slugs.ts`

`resolveEnglishAthleteSlugs(slugs, options)` возвращает
`Map<officialSlug, englishSlug>`.

Порядок работы: прочитать таблицу, отобрать недостающие слаги, загрузить их
страницы с параллельностью 4 и таймаутом 10 секунд на атлета, записать
найденные соответствия, вернуть объединённую карту.

Опции: `fetcher` (инжектируется, чтобы тестировать без сети) и `budgetMs`
(бюджет по времени, по умолчанию 90 000).

### Изменение `refreshUfcRankingSnapshot`

После `fetchUfcOfficialRankings()` собрать все `officialSlug` из чемпионов и
строк, вызвать резолвер, заменить слаги на английские там, где соответствие
найдено, и передать результат в `planUfcRankingSnapshotRefresh` как раньше.

## Обработка отказов

Основное правило: **резолв слагов не может ухудшить текущее состояние.**

- Ошибка сети, таймаут, отсутствие `hreflang` — слаг остаётся русским, строка
  падает на существующий фолбэк (`byName`, затем «Ожидается»).
- Падение одного атлета не влияет на остальных.
- Полный отказ резолвера не мешает записать снимок: рейтинг обновляется, как
  сегодня.

Первое обновление встречает около 150 неизвестных слагов, а UFC.com отвечает за
2–6 секунд. Поэтому у резолвера есть бюджет по времени: что не успели за 90
секунд, доедет следующим запуском крона. Чтобы не ждать несколько суток, кэш
прогревается скриптом `scripts/backfill-ufc-slug-aliases.js`.

## Тесты

`extractEnglishAthleteSlug`:

- фикстура ufc.ru возвращает английский слаг;
- «сломанный» случай `dzheremaya-uells-0` возвращает `tatsuro-taira`;
- страница без `hreflang` возвращает `null`.

`resolveEnglishAthleteSlugs` с фейковым фетчером:

- слаг из таблицы возвращается без сетевого запроса;
- ошибка на одном атлете не мешает разрешить остальных;
- исчерпание бюджета возвращает частичный результат без исключения;
- найденные соответствия записываются в таблицу.

`refreshUfcRankingSnapshot`:

- слаги в записанном payload заменены на английские;
- при полном отказе резолвера снимок всё равно пишется с русскими слагами.

## Критерий приёмки

После прогона бэкфилла и обновления снимка количество надписей «Ожидается» на
`/ru/rankings` падает со 124 до единиц. Проверяется подсчётом вхождений в
HTML-ответе прода.

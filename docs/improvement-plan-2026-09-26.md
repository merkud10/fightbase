# План улучшения FightBase

Дата: 26 сентября 2026 года.

Цель: повысить доверие к данным и прогнозам, упростить первый визит и обеспечить наблюдаемость автоматического обновления сайта.

Основание: проверка публичного сайта и текущего кода 26 сентября. Это рабочий план: выполненные пункты отмечаются только после проверки. Локальная реализация и публикация на production учитываются отдельно.

## Исходное состояние

- Основные проверенные публичные разделы, robots.txt, sitemap.xml и API health отвечают HTTP 200.
- Health сообщает 1 678 статей, 2 678 бойцов и 43 турнира. Числа относятся к моменту проверки и не означают, что все записи опубликованы или качественно заполнены.
- Локально: 344 теста прошли, один пропущен; TypeScript без ошибок.
- На главной рядом с пиком Барселоса показано «59% против 41%», хотя ему соответствует 41%.
- Health возвращает `ok: true`, несмотря на `backgroundJobs.status: error`, две неудачные задачи за последние шесть часов и предупреждение об устаревшем ingestion.
- На мобильной ширине 390 px кнопки главного блока начинаются примерно на 1316 px от начала страницы.
- В ближайшем карде встречаются нелокализованные имена; в проверенной новости лид обрезан и повторяет начало статьи.
- Открытая статистика модели: 31/53 (58%), виртуальный ROI −12%; фавориты: 35/51 (69%), ROI −5%. Выборки различаются; преимущества модели эти числа не подтверждают.
- Свежие Search Console, Метрика, Core Web Vitals и полный аудит безопасности в исходную проверку не входили.

## Порядок выпуска

1. Делать небольшие изменения по этапам, сохраняя результаты проверок здесь.
2. Для изменения логики использовать содержательные регрессионные тесты; для верстки — визуальную проверку.
3. Перед публикацией проверить diff и сборку; после публикации проверить реальные страницы и health.
4. Не считать локальную правку опубликованной. Не смешивать выпуск шаблонов с массовым изменением контента.
